                    ▲
                   ╱│╲         SECURITY LEVEL

              ╱ O  │ O      ╲    Risk: Anyone can modify
             ╱ T  │T E  ╲
            ╱ E   │ C   ╲     PROTECTED (Safer)

        ╱ D   │  DEFAULT  ╲  DEFAULT (Safer Still)
       ╱ │   │   PRIVATE   ╲ Same package access only
      ╱  │   │   (Safest)   ╲ Low risk

        Vehicle (Abstract Base Class)

        │           startEngine() ← Only subclasses override

⚠️ ANTI-PATTERN: EVERYTHING PUBLIC (DON'T DO THIS!)

    public class BadDesign {
        public String password;        ← Anyone can change!
        public List<User> users;       ← Anyone can modify!
        public double salary;          ← Anyone can read/change!

        public void dangerousMethod() {
            // Anyone can call and modify state
        }
    }

    // Problems:
    // ✗ No validation
    // ✗ Security risk
    // ✗ Hard to change later
    // ✗ Breaks if you need to add logic


✅ BETTER DESIGN: PROPER ENCAPSULATION

    public class GoodDesign {
        private String password;       ← Protected, validated
        private List<User> users;      ← Protected, can't modify
        private double salary;         ← Protected

        public void setPassword(String p) {
            if (isValidPassword(p)) {  // Validation layer
                this.password = p;
            }
        }

        public List<User> getUsers() {
            return new ArrayList<>(users);  // Return copy
        }

        private boolean isValidPassword(String p) {
            // Validation logic here
            return p != null && p.length() >= 8;
        }
    }

    // Benefits:
    // ✓ Data is protected
    // ✓ Validation enforced
    // ✓ Easy to change implementation
    // ✓ Secure by default
