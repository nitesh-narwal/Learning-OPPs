💡 KEY PRINCIPLES (GOLDEN RULES)

1. LEAST PRIVILEGE PRINCIPLE
   Make things PRIVATE by default
   Expand to PROTECTED, DEFAULT, PUBLIC only if needed
   
   ✓ Start Private → Protect by default
   ✓ Expand when necessary → Controlled access
   ✓ Never start Public → Breaks backward compatibility

2. ENCAPSULATION IS FUNDAMENTAL
   Hide internal implementation
   Expose only necessary interface
   Control all access to internal state
   
   ✓ Private data + Public interface = Encapsulation
   ✓ Getters/Setters with validation
   ✓ Immutable where possible

3. PUBLIC = CONTRACT
   Once you make something public, clients depend on it
   Changing the signature later breaks their code
   Think carefully before going public
   
   ✓ Choose public methods carefully
   ✓ Document the contract (JavaDoc)
   ✓ Think about backward compatibility

4. INHERITANCE NEEDS CAREFUL DESIGN
   Protected members are extension points
   Not safer than private
   Use protection in getters/setters
   
   ✓ Protect data even from subclasses
   ✓ Use protected methods for overriding
   ✓ Use template method pattern

5. PACKAGE ORGANIZATION
   Use default for internal utilities
   Use public for exported APIs
   Clear boundaries between packages
   
   ✓ Organize code by functionality
   ✓ Keep internals hidden
   ✓ Clean package interfaces

⚡ QUICK DECISION GUIDE (TLDR)

In a hurry? Use this:

Making a class or method?
├─ Others need it → PUBLIC
├─ Subclasses need it → PROTECTED
├─ Package mates need it → DEFAULT
└─ Only me → PRIVATE

Example:
├─ API method? → PUBLIC ✓
├─ Extension point? → PROTECTED ✓
├─ Utility for package? → DEFAULT ✓
├─ Internal helper? → PRIVATE ✓
