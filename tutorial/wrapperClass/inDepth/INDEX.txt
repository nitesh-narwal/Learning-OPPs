3️⃣ KEY TAKEAWAYS
═══════════════════════════════════════════════════════════════════════════════════

WHAT ARE WRAPPER CLASSES?
─────────────────────────
Wrapper classes are objects that "wrap" primitive values:
    boolean  ->  Boolean
    int      ->  Integer
    double   ->  Double
    ... and so on

WHY DO WE NEED THEM?
───────────────────
1. Collections only accept Objects (ArrayList<Integer>, not ArrayList<int>)
2. Some methods require Objects as parameters
3. We need utility methods on primitive values
4. We need to store null values (primitives cannot)

AUTO-BOXING & AUTO-UNBOXING
──────────────────────────
Since Java 5, the compiler automatically converts:
    Integer wrapped = 100;    // Auto-boxing: 100 -> Integer.valueOf(100)
    int primitive = wrapped;  // Auto-unboxing: wrapped.intValue()

THE MOST IMPORTANT RULE!
───────────────────────
❌ NEVER use == to compare wrapper objects
✓ ALWAYS use .equals() method

Why? Because caching makes == unpredictable:
    Integer a = 100;
    Integer b = 100;
    a == b;  // TRUE (both cached) <- This is confusing!

    Integer c = 200;
    Integer d = 200;
    c == d;  // FALSE (not cached) <- Inconsistent!

    a.equals(b);  // TRUE (compares values) <- Always works!
    c.equals(d);  // TRUE (compares values) <- Always works!

NULL HANDLING
─────────────
✓ Wrapper objects CAN be null
✗ Primitive values CANNOT be null

Unboxing null causes NullPointerException:
    Integer value = null;
    int primitive = value;  // ❌ NullPointerException!

Safe way:
    int safe = value != null ? value : 0;  // ✓ Correct

4️⃣ COMMON MISTAKES
═══════════════════════════════════════════════════════════════════════════════════

MISTAKE 1: Using == to compare wrapper objects
──────────────────────────────────────────────
❌ WRONG:
    Integer a = 100;
    Integer b = 100;
    if (a == b) { ... }  // Works due to caching (confusing!)

✓ CORRECT:
    if (a.equals(b)) { ... }  // Always works


MISTAKE 2: Unboxing null without checking
──────────────────────────────────────────
❌ WRONG:
    Integer value = null;
    int primitive = value;  // NullPointerException!

✓ CORRECT:
    int safe = value != null ? value : 0;


MISTAKE 3: Using wrappers in performance loops
──────────────────────────────────────────────
❌ WRONG:
    Long sum = 0L;
    for (int i = 0; i < 1000000; i++) {
        sum += i;  // Boxing/unboxing overhead!
    }

✓ CORRECT:
    long sum = 0L;
    for (int i = 0; i < 1000000; i++) {
        sum += i;  // No overhead
    }


MISTAKE 4: Assuming new Constructor and valueOf() are identical
──────────────────────────────────────────────────────────────
❌ WRONG:
    Integer obj1 = new Integer(100);
    Integer obj2 = new Integer(100);
    obj1 == obj2;  // FALSE (different objects)

✓ BETTER:
    Integer obj1 = Integer.valueOf(100);
    Integer obj2 = Integer.valueOf(100);
    obj1 == obj2;  // TRUE (cached object) - but don't rely on this!


MISTAKE 5: Comparing Float/Double with ==
──────────────────────────────────────────
❌ WRONG:
    double result = 0.1 + 0.2;
    if (result == 0.3) { ... }  // FALSE due to precision!

✓ CORRECT:
    double epsilon = 1e-9;
    if (Math.abs(result - 0.3) < epsilon) { ... }

5️⃣ ADVANCED CONCEPTS
═══════════════════════════════════════════════════════════════════════════════════

INTEGER CACHING
───────────────
Java caches Integer objects in range -128 to 127:

    Integer a = 100;   // Gets cached object
    Integer b = 100;   // Gets SAME cached object
    a == b;  // TRUE

    Integer c = 200;   // Creates new object (outside cache)
    Integer d = 200;   // Creates ANOTHER new object
    c == d;  // FALSE

Similar caching for: Boolean, Byte, Short, Long
NO caching for: Float, Double

CACHE RANGES:
    Integer:  -128 to 127
    Long:     -128 to 127
    Byte:     -128 to 127 (all possible values)
    Short:    -128 to 127
    Boolean:  true, false (only these two)
    Float:    NO CACHE
    Double:   NO CACHE

IMPORTANT: Caching is an implementation detail, NOT something to rely on!


BOXING VS UNBOXING PERFORMANCE
──────────────────────────────
Boxing and unboxing have performance cost:
- Primitives stored in Stack (fast)
- Wrapper objects stored in Heap (slower memory access)
- Boxing creates new object (memory allocation)
- Unboxing calls method (method call overhead)

In loops: primitives are 1-10x faster than wrappers!

WHEN TO USE PRIMITIVES:
    ✓ Loops and calculations
    ✓ Performance-critical code
    ✓ Memory-constrained environments

WHEN TO USE WRAPPERS:
    ✓ Collections (ArrayList, HashMap)
    ✓ API method parameters
    ✓ When you need null values
    ✓ When you need utility methods

6️⃣ QUICK REFERENCE
═══════════════════════════════════════════════════════════════════════════════════

PRIMITIVE TO WRAPPER MAPPING
────────────────────────────
boolean  →  Boolean
byte     →  Byte
char     →  Character
short    →  Short
int      →  Integer
long     →  Long
float    →  Float
double   →  Double


AUTO-BOXING AND UNBOXING RULES
──────────────────────────────
Auto-boxing:   Integer num = 100;         // Compiler: Integer.valueOf(100)
Auto-unboxing: int val = num;             // Compiler: num.intValue()

In operations:
    Integer a = 50;
    Integer b = 100;
    int sum = a + b;                      // Both auto-unboxed then added
    Integer wrapped = sum;                // Result auto-boxed


COMPARISON CHEAT SHEET
──────────────────────
✓ Use this:
    if (a.equals(b)) { }           // Compare values
    if (a.compareTo(b) < 0) { }    // Compare and order

❌ Don't use this:
    if (a == b) { }                // Reference comparison (unreliable)


NULL HANDLING PATTERNS
──────────────────────
Safe unboxing:
    Integer value = ...;
    int safe = value != null ? value : 0;

Or using Optional (Java 8+):
    Optional<Integer> value = ...;
    int safe = value.orElse(0);


COMMON CONVERSIONS
──────────────────
String → Integer:   int num = Integer.parseInt("100");
String → Double:    double num = Double.parseDouble("3.14");
String → Boolean:   boolean num = Boolean.parseBoolean("true");

Integer → String:   String str = Integer.toString(100);
Double → String:    String str = Double.toString(3.14);
Any → String:       String str = "" + value;


NUMBER BASE CONVERSIONS
───────────────────────
int num = 255;

Binary:     String bin = Integer.toBinaryString(num);     // "11111111"
Hex:        String hex = Integer.toHexString(num);        // "ff"
Octal:      String oct = Integer.toOctalString(num);      // "377"

Parse Binary:   int num = Integer.parseInt("11111111", 2);
Parse Hex:      int num = Integer.parseInt("FF", 16);
Parse Octal:    int num = Integer.parseInt("377", 8);
